01 Visão Geral e Objectivo

O SAEIF é um sistema de alerta em tempo real para incêndios florestais em Portugal Continental, desenvolvido como proof-of-concept pela TerraDigital. O seu propósito central é fornecer, nos primeiros minutos após a detecção de uma ignição, uma avaliação automática do potencial de crescimento do incêndio — cruzando dados satelitares, meteorológicos e de protecção civil — para apoio à decisão de mobilização.

Contexto operacional: Portugal perdeu mais de 500.000 hectares de floresta entre 2010 e 2023. A maioria dos grandes incêndios foi precedida por ignições aparentemente menores para as quais a mobilização inicial foi insuficiente. O SAEIF endereça directamente esta lacuna de avaliação precoce.

02 Fluxo Operacional

O sistema executa um pipeline sequencial de 5 etapas desde a detecção até à notificação, com um tempo máximo de 60 segundos end-to-end.

01

Detecção de ignição

Polling paralelo a três fontes: NASA FIRMS (hotspots VIIRS/MODIS por GeoJSON/CSV), fogos.pt scraping (fallback PROCIV) etiquetado SYS, e futuramente SGIF via API. Frequência: 5–15 minutos por fonte. Todos os alertas gerados pelo sistema são etiquetados source: SYS.

02

Deduplicação e geocodificação

Cruzamento FIRMS × PROCIV por proximidade geográfica de 40 km. Hotspots FIRMS já geocodificados por coordenada. Ocorrências PROCIV geocodificadas por nome de localidade (OSM Nominatim + fallback manual). Deduplicação por janela temporal de 30 minutos + raio de 2 km.

03

Enriquecimento meteorológico

Consulta à API IPMA para o ponto de ignição: temperatura, humidade relativa, velocidade e direcção do vento, índice FWI (Fire Weather Index). Os dados meteorológicos são o input dinâmico principal para o cálculo do score de risco.

04

Cálculo do score de risco e geração de ficha

Score composto (0–100) calculado a partir de: risco estrutural da paisagem, condições meteorológicas actuais (FWI, vento), tipo de combustível, declive, e índice de conectividade da paisagem. A ficha de alerta inclui mapa de propagação estimada a 6h/12h/24h, recomendação de mobilização, e identificação de infraestruturas em risco.

05

Notificação e dashboard

Actualização do dashboard via WebSocket (/ws) — o cliente recebe novos alertas sem necessidade de recarregar a página. Frontend em HTML/JS vanilla + Leaflet.js servido directamente pelo FastAPI como ficheiro estático (static/index.html). Notificações SYS registadas na base de dados. Futuramente: integração SGIF e notificações push para app mobile.

Nota de arquitectura: As funcionalidades de simulação (cenários hipotéticos sem ignição real detectada) foram removidas na totalidade do PoC. O sistema responde exclusivamente a ignições reais detectadas por pelo menos uma fonte.

05 Schema da Base de Dados

PostgreSQL 16 + PostGIS 3.4. Schema único public no PoC. Extensões: postgis, pgcrypto, pg_trgm.

CREATE TABLE hotspots (
    id              SERIAL PRIMARY KEY,
    source          VARCHAR(20) NOT NULL,        -- 'VIIRS' | 'MODIS'
    geom            GEOMETRY(POINT, 4326) NOT NULL,
    brightness      NUMERIC(6,2),                -- temperatura de brilho (K)
    frp             NUMERIC(8,2),                -- Fire Radiative Power (MW)
    confidence      VARCHAR(10),                 -- 'low' | 'nominal' | 'high'
    acq_date        DATE NOT NULL,
    acq_time        TIME NOT NULL,
    fetched_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    processed       BOOLEAN NOT NULL DEFAULT FALSE
);
CREATE INDEX ON hotspots USING GIST (geom);
CREATE INDEX ON hotspots (acq_date, processed);

-- Ocorrências PROCIV via fogos.pt

    id              SERIAL PRIMARY KEY,
    external_id     VARCHAR(50) UNIQUE,

    distrito        VARCHAR(100),
    concelho        VARCHAR(100),

07 Score de Risco e Recomendações de Mobilização

O score composto (0–100) é calculado em tempo real para cada ignição detectada, combinando componentes estruturais (estáticos, obtidos por lookup nos rasters locais) e meteorológicos (dinâmicos, via IPMA). Ver Secção 12 para a arquitectura completa dos mapas de risco.

Fórmula de cálculo (PoC)

# Componentes e pesos no PoC
# risco_estrutural: lookup geoespacial em fire_risk.tif (ver Secção 12)
score = (
    0.35 * risco_estrutural_normalizado    # raster lookup: CORINE + declive + NDVI (0–1)
  + 0.30 * fwi_normalizado                # Fire Weather Index IPMA (0–1)
  + 0.20 * vento_factor                   # vel > 50km/h → 1.0, < 10km/h → 0.1
  + 0.15 * confirmacao_prociv             # confirmado por PROCIV: +15 pts
) * 100

# Ajustamentos contextuais
if hotspot.confidence == 'low':   score *= 0.7
if hotspot.frp > 100:             score = min(score * 1.2, 100)  # FRP elevado

08 Integrações com Outros Sistemas

No contexto da arquitectura de 5 sistemas para a floresta portuguesa, o SAEIF é o consumidor final dos dados produzidos pelos sistemas a montante.

SIGCRF (S1)
Consulta de parcelas cadastradas na área de propagação estimada. Identifica proprietários em risco para notificação preventiva.
SMRIP (S3)
Consome risco estrutural, conectividade da paisagem, probabilidade de mega-incêndio e simulações de propagação. Principal produtor de dados para o score.
SGIF
Leitura de novas ocorrências via API. Escrita de dados de risco e propagação como anexo à ocorrência. Sincronização bidirecional de estado.
CDOS / AGIF
Destinatários das fichas de alerta. Dashboard operacional em tempo real. Futuramente: notificações push e integração com sistemas de comunicação.
IPMA
API REST pública. Dados horários de temperatura, humidade, vento e FWI para o ponto de ignição.
NASA FIRMS
API REST / GeoJSON. Hotspots VIIRS e MODIS em near-real-time para Portugal Continental (bbox definido).
Estado actual do PoC: As integrações com SIGCRF, SMRIP e SGIF são futuras. O PoC implementa apenas FIRMS + IPMA + fogos.pt, que são suficientes para demonstrar o fluxo operacional completo e validar a arquitectura.

12 Mapas de Risco de Incêndio

O SAEIF produz e consome dois tipos de mapas de risco no PoC: um raster de risco estrutural pré-calculado (fire_risk.tif), usado internamente no pipeline de scoring, e uma camada visual no frontend Leaflet que permite ao utilizador contextualizar cada hotspot no território de risco envolvente.

Princípio fundamental: O mapa de risco não é decorativo — é o componente com peso 0.35 no score de cada alerta. Um hotspot numa zona de risco estrutural elevado (floresta de resinosas densa, declive acentuado, vegetação seca) gera um score significativamente mais alto do que o mesmo hotspot numa zona agrícola ou urbana.

Pipeline de geração do raster de risco estrutural

O raster fire_risk.tif é calculado por um script Python (analysis/risk_raster.py) que combina três camadas de input, todas reprojectadas para EPSG:3763 (PT-TM06) a 100m de resolução:

# analysis/risk_raster.py — pipeline de geração de fire_risk.tif
import rasterio, numpy as np
from rasterio.warp import reproject, Resampling

# 1. CORINE Land Cover → valor de combustível (fuel)
corine_to_fuel = {
    # Florestas
    311: 1.0, 312: 1.0, 313: 0.95,    # folhosas / resinosas / mista
    324: 0.85,                          # vegetação arbustiva em transição
    322: 0.80, 323: 0.75,              # matos / charneca
    # Agricultura
    243: 0.35, 211: 0.15, 231: 0.20,
    # Urbano / água / artificial
    111: 0.0, 112: 0.0, 511: 0.0, 512: 0.0
}

# 2. EU-DEM → declive normalizado (slope_norm)
# gdal.DEMProcessing(slope.tif) → normalizar para 0–1 (0°=0, ≥45°=1)

# 3. Sentinel-2 NDVI → estado da vegetação
# ndvi_risk = 1 - ndvi_norm  (vegetação seca = risco alto)

# 4. Raster Calculator — pesos PoC
fire_risk = (
    0.50 * fuel_norm       # tipo de combustível: peso dominante
  + 0.30 * slope_norm      # declive: propagação acelerada em encosta
  + 0.20 * ndvi_risk       # estado da vegetação: seca = risco
)

# Output: fire_risk.tif — resolução 100m, EPSG:3763, valores 0.0–1.0
# Guardado em: /srv/saeif/api/data/fire_risk.tif
# Actualização: mensal (novo NDVI Sentinel-2)

Lookup geoespacial no pipeline de alertas

Para cada hotspot detectado, o módulo analysis/score.py extrai o valor do raster no ponto de ignição via rasterio:

import rasterio
from rasterio.transform import rowcol
from pyproj import Transformer

def get_structural_risk(lat: float, lon: float) -> float:
    """Extrai o valor de risco estrutural do raster para um ponto WGS84."""
    transformer = Transformer.from_crs("EPSG:4326", "EPSG:3763", always_xy=True)
    x, y = transformer.transform(lon, lat)

    with rasterio.open("/data/fire_risk.tif") as src:
        row, col = rowcol(src.transform, x, y)
        value = src.read(1)[row, col]
        return float(np.clip(value, 0.0, 1.0))

# Retorna valor normalizado 0.0 (risco nulo) → 1.0 (risco máximo)
# Valor é o risco_estrutural_normalizado usado no score composto

Opção A — WMS tile (preferida)
GeoServer local
O fire_risk.tif é publicado como camada WMS num GeoServer em container. O Leaflet consome-o como L.tileLayer.wms() com estilo SLD de 5 classes (verde → amarelo → laranja → vermelho → bordô). Permite zoom com resolução nativa. Requer container GeoServer adicional.
Opção B — GeoJSON simplificado (PoC)
Vectorização pré-calculada
O raster é vectorizado e simplificado para 5 classes de risco → GeoJSON de polígonos (~2–5 MB). Servido via GET /api/risk/map. O Leaflet aplica fill por classe. Sem dependência de GeoServer — solução simples e robusta para o PoC.
Decisão de arquitectura para o PoC: Usar a Opção B (GeoJSON simplificado). Evita a complexidade de um container GeoServer adicional. O GeoJSON de risco é gerado uma vez pelo script risk_raster.py e servido como ficheiro estático ou endpoint FastAPI. A transição para WMS (Opção A) fica reservada para quando o SMRIP estiver disponível.

Passo 2 — Download do novo layer (no servidor Hetzner)

cat > /tmp/download_novo_ano.py << 'EOF'
import requests, json, time, os

BASE = "https://sigservices.icnf.pt/server/rest/services/BDG/areas_ardidas/MapServer"
LAYER_ID = 21        # substituir pelo layer_id do novo ano
ANO = "2026"         # substituir pelo ano correcto
OUT = f"/srv/saeif/data/areas_ardidas/ardidas_{ANO}.geojson"
FIELDS = "OBJECTID,Ano,AreaHaPoly,DH_Inicio,DH_Fim,PI_Distrit,PI_Conc,PI_Freg,Causa_Tipo"
PAGE = 200

features, offset = [], 0
time.sleep(30)  # aguardar para evitar rate limiting

while True:
    url = (f"{BASE}/{LAYER_ID}/query?where=1%3D1&outFields={FIELDS}"
           f"&resultOffset={offset}&resultRecordCount={PAGE}"
           f"&returnGeometry=true&geometryPrecision=5&f=geojson")
    for attempt in range(5):
        try:
            r = requests.get(url, timeout=120)
            if r.status_code == 200 and r.text.strip():
                d = r.json()
                if "features" in d: break
        except Exception as e:
            print(f"  tentativa {attempt+1}: {e}")
        time.sleep(20 * (attempt + 1))
    else:
        print("Falhou definitivamente"); break
    batch = d.get("features", [])
    features.extend(batch)
    print(f"  offset={offset} +{len(batch)} total={len(features)}")
    if len(batch) < PAGE: break
    offset += PAGE
    time.sleep(15)

with open(OUT, "w") as f:
    json.dump({"type": "FeatureCollection", "features": features}, f)
print(f"Guardado: {len(features)} features em {OUT}")
EOF
python3 /tmp/download_novo_ano.py

Passo 3 — Importar para PostGIS

python3 << 'EOF'
import json, os, subprocess
from datetime import datetime, timezone

def ms_to_ts(ms):
    if not ms: return 'NULL'
    try:
        dt = datetime.fromtimestamp(int(ms)/1000, tz=timezone.utc)
        return f"'{dt.isoformat()}'"
    except: return 'NULL'

ANO = 2026  # substituir pelo ano correcto
path = f"/srv/saeif/data/areas_ardidas/ardidas_{ANO}.geojson"
d = json.load(open(path))
features = d.get('features', [])
print(f"{len(features)} features a importar")

sql_path = f"/tmp/import_{ANO}.sql"
with open(sql_path, 'w') as sql_f:
    for f in features:
        props = f.get('properties', {})
        geom  = f.get('geometry')
        if not geom: continue
        area_ha   = props.get('AreaHaPoly') or 0
        di_sql    = ms_to_ts(props.get('DH_Inicio'))
        df_sql    = ms_to_ts(props.get('DH_Fim'))
        distrito  = (props.get('PI_Distrit') or '').replace("'","''")[:50]
        concelho  = (props.get('PI_Conc') or '').replace("'","''")[:50]
        freguesia = (props.get('PI_Freg') or '').replace("'","''")[:50]
        causa     = (props.get('Causa_Tipo') or '').replace("'","''")[:50]
        gj        = json.dumps(geom).replace("'","''")
        sql_f.write(
            f"INSERT INTO areas_ardidas (ano,area_ha,data_inicio,data_fim,distrito,concelho,freguesia,causa_tipo,geom) "
            f"VALUES ({ANO},{area_ha},{di_sql},{df_sql},'{distrito}','{concelho}','{freguesia}','{causa}',"
            f"ST_Multi(ST_SetSRID(ST_GeomFromGeoJSON('{gj}'),4326))) ON CONFLICT DO NOTHING;\n"
        )

subprocess.run(['docker','compose','cp', sql_path, f'db:/tmp/import_{ANO}.sql'],
               cwd='/srv/saeif', check=True)
r = subprocess.run(
    ['docker','compose','exec','-T','db','psql','-U','saeif','-d','saeif',
     '-v','ON_ERROR_STOP=0','-f',f'/tmp/import_{ANO}.sql'],
    capture_output=True, text=True, cwd='/srv/saeif'
)
print(f"Inseridos: {r.stdout.count('INSERT 0 1')} Erros: {r.stderr.count('ERROR')}")
EOF
